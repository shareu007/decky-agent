# Codex 权限模式

在对话输入框下方选择模式，也可以在设置里选择。任务、录音或登录进行时不能切换；切换仅影响之后发出的任务，不新建对话，不清除输入草稿。旧配置默认迁移为“请求批准”。兼容 API 引擎继续使用自己的逐次工具审批，不受这组 Codex 选项影响。

| 模式 | 沙箱与审批 | 适用情况 |
| --- | --- | --- |
| 请求批准 | 工作目录沙箱；越界时由用户批准 | 希望检查软件安装命令、下载与写入位置 |
| 帮我批准 | 同一工作目录沙箱；越界时由 Codex 官方自动审核决定 | 希望持续执行已描述的任务，减少手动确认 |
| 完全访问 | 关闭 Codex 文件和网络沙箱，不请求 Codex 操作审批 | 已明确接受让 Agent 操作当前用户可访问的整个设备 |

“帮我批准”不是插件收到请求就全部返回允许。它向原生 Codex 传入 `approvalPolicy: on-request`、`approvalsReviewer: auto_review`；请求批准使用 `user` reviewer。完全访问使用 `never` 和 `danger-full-access`。新建、恢复线程和每轮任务都会重新应用策略，切回沙箱模式不会沿用上一轮完全访问设置。

官方审核进行中、批准、拒绝或超时会显示为可展开的工具记录，包含 Codex 返回的原因。如果 Codex 版本或组织策略没有实际启用自动审核，任务会明确报错，不会假装已经开启。

额外权限请求不再固定拒绝：界面展示确切请求，允许后只返回请求范围，并限定为当前轮次，不默认授予整个会话。命令审批显示命令、目录和原因；文件修改保留请求和差异信息。

## 软件安装与更新

模式控制的是 Codex 的沙箱和审批。插件始终以普通用户运行；“帮我批准”和“完全访问”都不等于 root，也不会自动取得 sudo 权限或处理 sudo 密码。用户级安装与系统级安装受 Linux 本身权限限制。插件不修改 sudoers、系统只读设置或 Bazzite 的系统管理方式。

## 验证

`scripts/smoke_permissions.py` 使用真实 Codex 0.164.0 和临时 localhost 模型服务，检查三种模式在同一原生线程上生效，再切回请求批准；不会运行安装命令、读取用户凭据或调用付费模型。单元测试另覆盖设置迁移、拒绝未知模式、额外权限的明确决策及当前轮次范围、自动审核结果回显，以及旧运行时未启用自动审核时的失败行为。

依据：[OpenAI 官方自动审核说明](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[官方 app-server 协议](https://learn.chatgpt.com/docs/app-server)，并以内置 0.164.0 导出的实际 JSON Schema 和协议响应核对。
